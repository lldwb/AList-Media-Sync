# 项目概述

> AList-Media-Sync 是一个基于 Spring Boot 4.1.0 + Java 21 的 AList 网盘媒体同步与转码服务，对接 B 站录播姬 Webhook 自动触发，配套 React 19 + TypeScript Web 管理前端。

## 项目背景

AList 是一款流行的开源网盘聚合工具，支持多种存储后端的统一挂载与文件管理。B 站录播姬（Danmuji）是直播录制工具，录制结束后会通过 Webhook 推送事件。本项目的核心诉求是：

1. **自动同步**：将录播姬产出的媒体文件自动同步到 AList 挂载的目标目录，无需人工搬运；
2. **自动转码**：对原始录制文件（FLV/MP4 等）按需转码为 MP3/MP4/FLV 等目标格式，降低存储与播放成本；
3. **事件驱动**：接收录播姬 Webhook v2 事件，通过规则匹配自动触发对应同步与转码任务；
4. **可视管理**：提供 Web 管理界面统一管理存储引擎、同步任务、转码任务、Webhook 规则，并通过 WebSocket 实时推送进度。

项目定位为**单实例自托管服务**，面向个人或小团队部署，不追求多租户与集群能力。

## 核心功能清单

| # | 功能模块 | 简述 |
|---|---------|------|
| 1 | 存储引擎 | 策略模式抽象文件操作接口，内置 AList 远程存储与本地文件系统两种策略；新增后端只需实现接口并注册为 Spring 组件。支持引擎 CRUD、连接测试、目录浏览。 |
| 2 | 文件同步 | 提供 NEW_ONLY（仅新增）、FULL（全量覆盖）、MOVE（移动）三种同步模式；支持 CRON 表达式与 INTERVAL 固定间隔两种调度方式；采用扫描→比对→执行三阶段流水线，大文件（>100MB）走临时文件中转，小文件直接流式传输。 |
| 3 | 媒体转码 | 下载→FFmpeg 转码→上传三步流程，8 状态模型精确刻画生命周期；通过 JAVE2 封装 FFmpeg，`Semaphore` 控制并发（默认上限 32）；支持原目录转码、失败重试从断点续做、临时后缀自定义、转码前磁盘空间预检。 |
| 4 | Webhook | 接收录播姬 Webhook v2 事件，EventId 去重保证幂等；规则匹配后触发同步、转码或两者并行；规则支持按事件类型、文件路径等条件配置动作（SYNC_ONLY / TRANSCODE_ONLY / BOTH）。 |
| 5 | Web 管理界面 | React 19 + TypeScript + Vite 构建的 SPA，构建产物输出到 `src/main/resources/static/app/`；包含认证登录、仪表板、存储引擎、同步任务、转码监控、Webhook 规则等页面；通过 Hash 路由部署在 `/app/` 路径下。 |
| 6 | WebSocket 实时进度 | 通过 `/ws/events` 端点向已认证的前端会话推送任务进度、状态变更等消息；消息以 `type` 字符串标识区分（SYNC_PROGRESS、TRANSCODE_PROGRESS、TASK_EVENT、WEBHOOK_EVENT）。 |
| 7 | 轻量诊断 | 统一 traceId 贯穿任务执行与 HTTP 请求；所有 `/api/**` 响应携带 `X-Trace-Id`；ERROR 日志分流到独立 `error.log`；一键生成自动脱敏的诊断包，便于将"问题摘要"交给 AI 或开发者排查。 |

## 技术栈

### 后端

| 层 | 技术 |
|---|------|
| 框架 | Spring Boot 4.1.0 |
| 语言 | Java 21（LTS，启用虚拟线程） |
| 持久层 | Spring Data JPA + Hibernate + H2（文件模式，单实例） |
| 转码引擎 | JAVE2 3.5.0（ws.schild）封装 FFmpeg |
| 加密 | AES-256-GCM（Token 字段级加密，`CryptoConverter`）+ BCrypt（登录密码哈希，随机盐值，仅存内存） |
| HTTP 客户端 | Spring RestClient（调用 AList REST API） |
| 实体简化 | Lombok（@Getter / @Setter / @NoArgsConstructor 等） |
| 构建 | Maven Wrapper（`./mvnw`，无需预装 Maven） |

### 前端

| 层 | 技术 |
|---|------|
| 框架 | React 19 |
| 语言 | TypeScript |
| 构建 | Vite 6 |
| 路由 | React Router（Hash 模式） |
| 部署 | 构建产物输出到 `src/main/resources/static/app/`，由 Spring Boot 静态资源服务 |

### 基础设施

| 层 | 技术 |
|---|------|
| 容器化 | Docker 多阶段构建（frontend-build → builder → runtime）+ Docker Compose 编排 |
| 一体化启动包 | Maven Assembly 打包，内置 JRE，解压即用 |
| 日志 | Logback，按天滚动，单文件 ≤50MB，保留 30 天 |

## 非目标边界

为避免功能蔓延、保持项目聚焦，以下明确**不在本项目范围内**：

- **多租户**：不做租户隔离、按租户配额等能力，仅支持单用户（admin）自托管场景；
- **外部数据库**：不引入 PostgreSQL / MySQL 等外部数据库，固定使用 H2 文件模式单实例；如需多实例部署需自行改造持久层；
- **转码集群**：不做分布式转码调度，转码并发仅靠单机 `Semaphore` 控制；
- **CDN / 反向代理集成**：不内置 CDN 回源或反代配置，由部署方在外部（Nginx 等）处理；
- **非录播姬事件源**：Webhook 仅适配录播姬 v2 协议，不通用化接收任意第三方 Webhook。
