# 开发环境搭建

本篇面向从源码参与开发或本地调试的贡献者。如需 Docker 或一体化启动包部署，请参考 [README.md](../README.md) 的快速开始章节。

## 1. JDK 21 安装

本项目依赖 Java 21 LTS，并启用虚拟线程特性，低于 JDK 21 无法运行。

1. 下载并安装 JDK 21（推荐发行版：Oracle JDK 21、Eclipse Temurin 21、Amazon Corretto 21）；
2. 配置环境变量 `JAVA_HOME` 指向 JDK 安装目录（如 `C:\Program Files\Java\jdk-21` 或 `/usr/lib/jvm/temurin-21`）；
3. 将 `%JAVA_HOME%\bin`（Windows）或 `$JAVA_HOME/bin`（Linux）加入 `PATH`；
4. 验证：

```bash
java -version
# 预期输出包含 "21" 版本号，例如：openjdk version "21.0.x"
```

> 虚拟线程由 Spring Boot 4.1.0 自动启用，无需额外配置。

## 2. Maven Wrapper

项目内置 Maven Wrapper，无需预装 Maven。

```bash
# Linux / macOS / Git Bash
./mvnw spring-boot:run

# Windows CMD / PowerShell
mvnw.cmd spring-boot:run

# 运行全部测试
./mvnw test
```

若需使用全局 Maven，要求版本 ≥ 3.9。

## 3. 前端构建

前端源码位于 `src/main/frontend/`，需 Node.js 22+。

```bash
cd src/main/frontend
npm ci            # 严格按 lockfile 安装依赖
npm run build     # 构建产物输出到 dist/，随后复制到 src/main/resources/static/app/
```

构建完成后，Spring Boot 启动时由 `WebMvcConfig` 将 `/app/**` 路径映射到 `static/app/` 静态资源。

开发期可使用热更新：

```bash
cd src/main/frontend
npm run dev       # Vite 开发服务器，默认 http://localhost:5173
```

> 开发服务器默认通过代理将 `/api/**` 转发到后端 `http://localhost:8080`，具体代理配置见 `src/main/frontend/vite.config.ts`。

## 4. 本地必填配置

以下环境变量在本地开发时**必须配置**，否则启动后无法连接 AList：

| 环境变量 | 必填 | 说明 |
|---------|------|------|
| `ALIST_BASE_URL` | 是 | AList 服务器地址，如 `https://your-alist.example.com` |
| `ALIST_TOKEN` | 是 | AList API 认证令牌，从 AList 管理后台获取 |
| `ALIST_CRYPTO_KEY` | 否（生产必设） | AES-256 密钥，Base64 编码的 32 字节明文；缺失时启动随机生成，重启后已加密数据不可解密 |

以下为常用可选配置：

| 环境变量 | 默认值 | 说明 |
|---------|--------|------|
| `DATA_DIR` | `./data` | H2 数据库文件存储目录，对应配置项 `app.data-dir` |
| `APP_AUTH_PASSWORD` | `admin123` | 管理后台登录密码，覆盖配置项 `app.auth.password` |
| `SERVER_PORT` | `8080` | 应用 HTTP 监听端口 |
| `LOGGING_LEVEL` | `INFO` | 日志级别：TRACE / DEBUG / INFO / WARN / ERROR |

> 完整配置项清单见 `docs/operations/` 下的配置详解，以及 `src/main/resources/application.yaml`。

## 5. 启动方式

### 5.1 Maven Wrapper 启动

```bash
# 配置必填环境变量后（Linux）
export ALIST_BASE_URL=https://your-alist.example.com
export ALIST_TOKEN=your-token
./mvnw spring-boot:run
```

Windows 下可使用 `set` 或 PowerShell `$env:` 设置环境变量，再用 `mvnw.cmd spring-boot:run` 启动。

### 5.2 IDE 启动

主类为 `top.lldwb.alistmediasync.AListMediaSyncApplication`（`src/main/java/top/lldwb/alistmediasync/AListMediaSyncApplication.java`）。

在 IDEA / Eclipse 中：
1. 直接右键主类 → Run；
2. 在 Run Configuration 中添加上述必填环境变量；
3. Spring Boot 自动加载 `application.yaml`，无需额外参数。

### 5.3 一体化启动包脚本

```bash
# 打包（跳过测试加速）
./mvnw package -DskipTests
# 产物位于 target/alist-media-sync-{version}-*.zip / *.tar.gz

# 解压后编辑 config/application.yaml 填入 AList 连接信息
# Linux
./start.sh
# Windows
start.bat
```

启动后访问 http://localhost:8080/app/ ，默认账号 `admin` / `admin123`。

## 6. 常见启动问题排障

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| 端口 8080 已被占用 | 其他进程占用同一端口 | 修改 `SERVER_PORT` 环境变量或 `application.yaml` 中的 `server.port`；或终止占用端口的进程 |
| H2 初始化失败 / 数据库锁 | `DATA_DIR` 路径无写权限，或同一数据目录已有实例运行 | 检查 `DATA_DIR` 目录权限；确保同一 `DATA_DIR` 仅运行一个实例（H2 文件模式不支持并发写入） |
| 访问 `/app/` 返回 404 | 前端未构建，`src/main/resources/static/app/` 目录为空 | 执行 `cd src/main/frontend && npm ci && npm run build`，产物会自动复制到 `static/app/` |
| 启动后 AList 接口 401 / 连接失败 | `ALIST_TOKEN` 未配置或已失效 | 重新从 AList 管理后台获取令牌，更新 `ALIST_TOKEN` 环境变量 |
| 重启后已加密 Token 不可解密 | `ALIST_CRYPTO_KEY` 缺失，上次启动随机生成密钥，重启后密钥变化 | 生产环境务必固定配置 `ALIST_CRYPTO_KEY`，并在 AList 管理后台重新录入 Token |
| 前端构建报 `npm ci` 失败 | Node 版本过低或 lockfile 不一致 | 升级 Node.js 至 22+；删除 `node_modules` 后重新 `npm ci` |

## 7. 端到端测试环境搭建

本项目测试分为三层：单元测试（`mvn test`）、集成测试（`mvn verify -Pintegration`）、端到端测试（`mvn verify -Pe2e`）。前两层无需外部依赖，端到端测试需准备真实 AList 二进制实例。

### 7.1 测试 Profile 说明

| 命令 | 执行范围 | 外部依赖 | 预期耗时 |
|------|---------|---------|---------|
| `./mvnw test` | 单元测试（`*Test.java`） | 无 | < 60 秒 |
| `./mvnw verify -Pintegration` | 单元 + 集成测试（`*IT.java`） | 无（H2 内存 + WireMock 进程内） | < 120 秒 |
| `./mvnw verify -Pe2e` | 单元 + 集成 + 端到端测试（`*E2ETest.java`） | AList 二进制（录播姬可选） | 单链路 < 5 分钟，全套约 60 分钟 |

E2E 测试默认通过 `@EnabledIfEnvironmentVariable(RUN_E2E=true)` 跳过，仅在显式启用时执行，避免无 AList 二进制环境下构建失败。

### 7.2 准备 AList 二进制（一键脚本）

```powershell
# Windows：下载 AList 二进制到 scripts/e2e/bin/alist/（幂等，已存在则跳过）
.\scripts\e2e\prepare-e2e-env.ps1

# 可选：同时下载录播姬二进制用于真实 webhook 格式验证
.\scripts\e2e\prepare-e2e-env.ps1 -IncludeDanmuji

# Linux 备选
./scripts/e2e/prepare-e2e-env.sh
```

脚本特性：版本锁定、SHA256 校验、幂等跳过已存在下载。首次下载需网络可达 GitHub Releases。

### 7.3 使用本地已有 AList 二进制

若已手动准备 AList 二进制，可通过环境变量跳过下载：

```bash
# 指定本地 AList 可执行文件路径
export ALIST_LOCAL_PATH=/path/to/alist

# 启用 E2E 测试执行
export RUN_E2E=true
./mvnw verify -Pe2e
```

### 7.4 动态端口分配

E2E 测试采用动态端口分配（FR-014）：`E2ELifecycleManager` 通过 `ServerSocket(0)` 探测空闲端口，注入到 AList、录播姬与系统实例配置中，消除端口占用冲突风险，无需手动指定固定端口。端口分配结果写入 `scripts/e2e/data/ports.json`（已加入 `.gitignore`）。

### 7.5 E2E 失败现场保留

测试中途失败时保留数据库与文件系统现场（位于 `./data-e2e/`），供维护者通过诊断脚本定位问题；下次运行前由 `@BeforeAll` 强制清理保证幂等。诊断命令：

```bash
./scripts/diagnose.sh        # Linux
.\scripts\diagnose.bat       # Windows
```
