# 03-架构设计

> 本文档为 AList-Media-Sync 项目的架构设计总览，遵循章程原则 I（分层架构）。各模块细化文档见 [docs/architecture/](./architecture/)。

## 分层架构

项目采用 Spring Boot 经典三层架构（章程原则 I — 不可协商）：

```
┌─────────────────────────────────────────────────────────┐
│                    Controller 层                         │
│  HTTP 请求处理 · 参数校验 · 响应封装 · ApiResult<T>       │
│  MUST NOT 包含业务逻辑                                    │
└────────────────────────┬────────────────────────────────┘
                         │ 依赖注入
┌────────────────────────┴────────────────────────────────┐
│                     Service 层                           │
│  核心业务逻辑 · 事务管理 · @Transactional · 策略分发       │
│  保持对 Controller 和 Repository 的双向解耦               │
└────────────────────────┬────────────────────────────────┘
                         │ 依赖注入
┌────────────────────────┴────────────────────────────────┐
│                    Repository 层                         │
│  数据持久化 · Spring Data JPA 接口定义 · 禁止自定义 SQL    │
│  （除非经批准的性能优化）                                  │
└────────────────────────┬────────────────────────────────┘
                         │
┌────────────────────────┴────────────────────────────────┐
│                      Entity 层                           │
│  JPA 实体 · @Version 乐观锁 · @Table 映射                │
└─────────────────────────────────────────────────────────┘
```

### 层级职责

- **Controller 层**：仅负责 HTTP 请求处理、参数校验（Jakarta Validation）、响应封装（统一使用 `ApiResult<T>`）。不包含任何业务逻辑，不直接调用 Repository。
- **Service 层**：承载核心业务逻辑与事务管理（`@Transactional`）。保持对 Controller 和 Repository 的双向解耦（通过依赖注入）。策略模式在此层实现（如 `StorageEngineService` 的策略分发）。
- **Repository 层**：仅负责数据持久化，使用 Spring Data JPA 接口定义。禁止自定义 SQL（除非经批准的性能优化）。
- **Entity 层**：JPA 实体定义，所有实体 MUST 定义 `@Version` 字段用于乐观锁控制（章程原则 II）。

### 禁止事项

- Controller 直接调用 Repository（跨层调用）MUST 在代码审查中被拒绝
- Entity 直接暴露给 API 响应（MUST 通过 DTO/VO 转换，章程原则 III）
- 跨模块直接调用 Service 的私有方法（通过公共接口或事件机制解耦）

## 核心类职责说明

### 配置层

#### AppProperties

`@ConfigurationProperties(prefix = "app")`，绑定所有 `app.*` 配置，是配置层的唯一入口。包含 auth（认证）、transcode（转码）、pool（线程池）、dataDir（数据目录）、retentionDays（保留天数）等子配置组。所有配置项通过此类访问，禁止散落的 `@Value` 注解。

#### 各 Config 类

| 类 | 职责 |
|---|------|
| `AsyncConfig` | 配置 `transcodeExecutor` 线程池（核 8 / 最大 32 / 队 64 / `CallerRunsPolicy`） |
| `WebMvcConfig` | 拦截器注册（`AuthInterceptor` + MCP 启用时的 `McpAuthInterceptor`）、CORS、SPA 静态资源映射 `/app/**` |
| `McpConfig` | MCP 服务器装配开关（`@ConditionalOnProperty(app.mcp.enabled=true)`）与启动令牌校验，令牌为空时拒绝启用 |
| `WebSocketConfig` | 注册 `/ws/events` 端点，绑定 `WebSocketAuthInterceptor` |
| `RestClientConfig` | 手动注册 `RestClient.Builder` Bean（Spring Boot 4.x 不自动注册），配置请求/响应拦截器 |
| `TraceIdFilter` | `OncePerRequestFilter`，全链路追踪入口，注入 traceId 到 MDC 和 `X-Trace-Id` 响应头 |
| `GlobalExceptionHandler` | `@RestControllerAdvice` 全局异常处理，统一转换为 `ApiResult<T>` |
| `CryptoKeyEnvironmentPostProcessor` | `EnvironmentPostProcessor`，将 `ALIST_CRYPTO_KEY` 桥接到 JVM 系统属性 |
| `PasswordEncryptionPostProcessor` | `EnvironmentPostProcessor`，启动时 BCrypt 加密明文密码到内存 |
| `OpenApiConfig` | `@OpenAPIDefinition` + `@SecurityScheme`，OpenAPI 文档配置 |

### 认证与追踪

#### TraceIdFilter + TraceContext + MDC

全链路追踪机制：

- `TraceIdFilter` 在请求入口生成或继承 traceId，写入 SLF4J MDC
- `TraceContext` 提供 `runWith(traceId, module, operation, runnable)` 便捷入口，任务结束后自动清理 MDC
- MDC 结构化字段：`traceId` / `module` / `operation` / `errorType`
- 所有 `/api/**` 响应携带 `X-Trace-Id` 响应头

#### AuthInterceptor + WebSocketAuthInterceptor

- `AuthInterceptor`：HTTP Basic 认证拦截器（约 80 行），排除 `/api/webhooks/**`、`/actuator/health`
- `WebSocketAuthInterceptor`：WebSocket 握手阶段 Basic Auth 校验
- 密码比对使用 BCrypt（仅使用 Spring Security Crypto，不引入完整 Security 框架，YAGNI）

#### CryptoConverter

JPA `AttributeConverter`，使用 AES-256-GCM 自动加密/解密数据库字段。被 `StorageEngine` 实体的 Token 字段使用。密钥来源为 `ALIST_CRYPTO_KEY` 环境变量（由 `CryptoKeyEnvironmentPostProcessor` 桥接）。

#### GlobalExceptionHandler

`@RestControllerAdvice`，将业务异常、校验异常、未捕获异常统一转换为 `ApiResult<T>` 响应，包含 code / message / data 字段。

#### OpenApiConfig

`@Configuration`，配置 OpenAPI 文档元信息与 Basic 认证安全方案，供 `/swagger-ui.html` 端点使用。

## MCP 接入层（AI 操作接口）

> MCP 服务器嵌入主应用同进程同端口，端点 `POST /mcp`（Streamable HTTP，MCP 2025-03-26 规范），默认禁用（FR-012）。详细设计见 `specs/013-mcp-server/`。

### 分层位置

MCP 工具层与 `controller/` 并列作为**协议入口**：Controller 是 HTTP REST 入口，MCP 工具是 AI 协议入口。二者同层复用 Service 层，MUST NOT 直调 Repository 或承载业务逻辑（原则 I）。

### 核心类

| 类 | 包 | 职责 |
|---|-----|------|
| `McpConfig` | `common/config/` | 装配开关 + 启动令牌校验（`@ConditionalOnProperty`） |
| `McpAuthInterceptor` | `common/interceptor/` | 独立 Bearer Token 认证（恒定时间比较），与 Web Basic Auth 隔离（FR-008） |
| `McpToolResult` | `common/mcp/` | 工具结果统一封装：TraceContext 注入（FR-010）、异常→统一错误结构（FR-015） |
| `StorageEngineMcpTools` | `storage/mcp/` | 存储引擎 8 工具（FR-003） |
| `SyncTaskMcpTools` | `sync/mcp/` | 同步任务 9 工具（FR-004） |
| `SyncFlowMcpTools` | `sync/mcp/` | 流程级快捷工具「创建并触发一次同步」（FR-013） |
| `TranscodeTaskMcpTools` | `transcode/mcp/` | 转码任务 8 工具（FR-005） |
| `WebhookMcpTools` | `webhook/mcp/` | Webhook 规则/事件 8 工具（FR-006，无事件注入） |
| `SystemMcpTools` | `common/mcp/` | 系统运维 2 工具（FR-007） |

### 关键机制

- **默认禁用**：`app.mcp.enabled=false`（默认），仅显式开启且令牌非空时 MCP bean 与端点才装配；`spring.ai.mcp.server.*` 由 `app.mcp.*` 派生保持一致
- **认证先于协议**：`McpAuthInterceptor` 拦截 `/mcp` 全部请求（含 `initialize` 握手），认证失败 401 且不泄露业务数据（SC-004）
- **工具注册**：`@McpTool` / `@McpToolParam` 注解 + Spring AI 注解扫描自动注册，5+1 个工具类共 36 个工具
- **可观测性**：每次工具调用经 `McpToolResult` 注入 traceId / module=mcp / operation=工具名 日志（SC-003）；敏感凭据脱敏后返回（FR-011）
- **长任务异步提交**：触发同步/转码的工具立即返回任务 ID，AI 通过查询工具轮询结果（FR-014）

## 模块间依赖关系

```
                    ┌──────────┐
                    │ webhook  │
                    └────┬─────┘
              ┌──────────┼──────────┐
              ↓          ↓          │
        ┌──────────┐ ┌──────────┐  │
        │   sync   │ │ transcode│  │
        └────┬─────┘ └────┬─────┘  │
              │            │        │
              └──────┬─────┘────────┘
                     ↓
              ┌──────────┐
              │ storage  │
              └────┬─────┘
                   ↓
              ┌──────────┐
              │  common  │
              └──────────┘
```

### 依赖说明

- **webhook → sync**：Webhook 规则匹配后触发同步任务（`WebhookService` 调用 `SyncService`）
- **webhook → transcode**：Webhook 规则匹配后触发转码任务（`WebhookService` 调用 `TranscodeService`）
- **webhook → storage**：Webhook 触发后的文件操作通过策略接口
- **sync → storage**：同步任务通过 `StorageEngineStrategy` 接口操作源和目标存储；同引擎复制走 `copyFile`（服务端复制）
- **sync → transcode**（可选）：同步任务可配置 `transcodeEnabled` 自动触发转码
- **transcode → storage**：转码流程中的下载和上传步骤通过策略接口
- **sync → common**：DTO/VO、工具类、`WsSessionManager`（进度推送）
- **transcode → common**：`TempFileManager`、`DiskSpaceChecker`、`MagicBytesDetector`、`WsSessionManager`
- **webhook → common**：DTO/VO、认证排除配置
- **所有模块 → common**：配置、认证、异常处理、工具类等共享基础设施

### 依赖方向约束

- common 不依赖任何业务模块（仅提供基础设施）
- storage 不依赖 sync / transcode / webhook（仅被依赖）
- sync 和 transcode 不直接相互依赖（通过 webhook 间接协作，或 sync 可选调用 transcode）
- webhook 依赖 sync 和 transcode（触发任务）

## 架构设计原则

1. **策略模式**：存储引擎通过 `StorageEngineStrategy` 接口抽象，新增后端只需实现接口 + `@Component` 注解（[模块-storage.md](./architecture/模块-storage.md)）
2. **YAGNI**：认证使用自定义拦截器（80 行），不引入 Spring Security；策略接口仅在第二个实现出现后引入（章程原则 VI）
3. **密码安全**：仅支持明文配置，启动时 BCrypt 加密到内存，绝不回写文件
4. **Token 加密**：`CryptoConverter` 使用 AES-256-GCM 自动加密/解密数据库中的 Token
5. **并发控制**：转码使用 `Semaphore` 限流，线程池核 8 / 最大 32，拒绝策略 `CallerRunsPolicy`
6. **优雅关闭**：应用 12s 关闭超时 + Docker Compose 35s 停止宽限期
7. **健康检查**：通过 `/actuator/health` 端点暴露
