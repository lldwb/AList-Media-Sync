# 功能规格：MCP 服务器（AI 操作接口）

**功能分支**：`013-mcp-server`

**创建日期**：2026-08-16

**状态**：已完成

**输入**：用户描述："添加MCP服务器的功能，让AI可以操作，把主要流程提取成工具，一个mcp根据不同模块提供多个工具"

## 澄清

### 会话 2026-08-16

- Q: MCP 工具粒度设计？ -> A: 混合模式——操作级细粒度工具为主（覆盖现有 Web 管理 API 全部核心操作面），另提供少量流程级快捷工具供常见业务场景一键完成（FR-013）
- Q: MCP 访问认证方式？ -> A: 独立 Bearer Token——新增 MCP 专用访问令牌配置项，与 Web 管理界面 Basic Auth 凭据隔离（FR-008）
- Q: 是否提供「模拟发送 Webhook 事件」工具？ -> A: 不提供——MCP 仅提供事件查询工具，事件由外部系统（录播姬）真实触发；事件注入属测试能力，由 E2E 重放工具覆盖（FR-006）
- Q: MCP 服务器默认启用还是禁用？ -> A: 默认禁用——需显式配置开启，未配置 Bearer Token 时强制不可用（FR-012）
- Q: MCP 工具调用是否需要额外并发/限流控制？ -> A: 不额外限流——复用现有 Service 层并发控制，若实测出现调用风暴再补充限流（假设）

## 用户场景与测试 *（强制）*

### 用户故事 1 — 存储引擎模块工具：AI 管理存储引擎并浏览目录（优先级：P1）

作为 AI 助手（如 Claude Code），我希望通过 MCP 服务器管理存储引擎（创建/更新/删除/查询/测试连接），并浏览存储引擎的目录与文件，以在帮助用户配置存储或选择同步/转码的源与目标路径时，直接完成存储侧的操作。

**为什么是此优先级**：存储引擎是所有业务链路（同步、转码）的基础资源。没有存储侧工具，AI 无法为同步/转码流程提供端到端操作能力，它是其余模块工具的地基。

**独立测试**：可以通过"连接 MCP 服务器 → 调用存储引擎创建/查询/连接测试/目录浏览工具 → 验证结果与 Web 界面一致"完整测试并交付"AI 可操作存储引擎"的价值。

**验收场景**：

1. **假设** MCP 服务器已启用且 AI 已通过认证，**当** AI 调用"列出存储引擎"工具，**则** 返回系统当前所有存储引擎及其状态
2. **假设** AI 提供合法的存储引擎配置（类型、地址、凭据），**当** AI 调用"创建存储引擎"工具，**则** 创建成功并返回新引擎详情，结果可在 Web 管理界面看到
3. **假设** AI 指定某存储引擎与目录路径，**当** AI 调用"浏览目录/文件"工具，**则** 返回该路径下的目录与文件条目，与 Web 界面结果一致
4. **假设** AI 提供无效参数或不存在的主键 ID，**当** AI 调用存储引擎工具，**则** 返回清晰的错误信息，不产生部分写入

### 用户故事 2 — 同步任务模块工具：AI 查询与触发同步流程（优先级：P1）

作为 AI 助手，我希望通过 MCP 服务器创建、查询、触发、启停同步任务并查看执行历史，以在用户提出"帮我同步某目录""查看同步进度"等诉求时，直接驱动同步流程执行。

**为什么是此优先级**：文件同步是系统核心业务。让 AI 能完成"创建任务 → 触发执行 → 查看结果"的完整同步链路，是 MCP 价值最大的场景之一。

**独立测试**：可以通过"调用同步任务工具创建并触发一个任务 → 等待执行 → 查看执行历史与状态"完整测试并交付"AI 可操作同步流程"的价值。

**验收场景**：

1. **假设** AI 提供同步任务配置（源/目标存储、模式），**当** AI 调用"创建同步任务"工具，**则** 任务创建成功并进入待调度状态
2. **假设** 存在已创建的同步任务，**当** AI 调用"手动触发执行"工具，**则** 任务开始异步执行，工具返回任务 ID，后续可通过"查询执行历史"工具追踪结果
3. **假设** 同步任务正在运行，**当** AI 调用"查询任务状态/执行历史"工具，**则** 返回当前状态与历史执行记录
4. **假设** AI 调用"启用/禁用定时调度"工具，**则** 任务定时调度状态正确切换

### 用户故事 3 — 转码任务模块工具：AI 创建与监控转码流程（优先级：P2）

作为 AI 助手，我希望通过 MCP 服务器创建转码任务、查询进度、重试失败任务并清理临时文件，以在用户提出"把某视频转成 mp4"等诉求时，驱动转码流程并处理异常。

**为什么是此优先级**：转码是重要但相对独立的业务模块。在存储与同步工具可用后，转码工具补齐第二大的操作面。

**独立测试**：可以通过"调用转码工具创建任务 → 查询实时进度 → 触发重试/清理"完整测试并交付"AI 可操作转码流程"的价值。

**验收场景**：

1. **假设** AI 提供源文件/目标格式等合法参数，**当** AI 调用"创建转码任务"工具，**则** 任务创建并异步开始执行（下载→转码→上传）
2. **假设** 转码任务执行中，**当** AI 调用"查询任务详情"工具，**则** 返回当前状态与实时进度
3. **假设** 存在失败状态的转码任务，**当** AI 调用"重试任务"工具，**则** 任务按失败阶段重新执行对应步骤
4. **假设** 存在残留临时文件，**当** AI 调用"清理临时文件"工具，**则** 删除残留文件并返回删除数量

### 用户故事 4 — Webhook 模块工具：AI 管理规则与查看事件（优先级：P2）

**独立测试**：可以通过"调用 Webhook 规则工具创建规则并启用 → 查询事件记录（事件由真实外部触发）"完整测试并交付"AI 可操作 Webhook 配置"的价值。

**验收场景**：

### 边界情况

- 当 MCP 服务器未启用（配置关闭）时，现有 Web 管理界面与 `/api/**` API 功能 MUST 完全不受影响
- 当 AI 客户端使用错误或缺失的凭据连接 MCP 时，系统 MUST 拒绝访问并给出明确错误，MUST NOT 泄露任何业务数据
- 当多个 AI 客户端并发调用 MCP 工具时，MUST 保证线程安全，且每个调用携带独立 traceId，日志不串扰（章程原则 VII）
- 当 AI 调用触发长时间任务（同步/转码）的工具时，工具 MUST 采用异步提交并立即返回任务 ID，不得阻塞等待任务完成
- 当 AI 传递非法参数（不存在的 ID、非法枚举、空必填字段）时，MUST 返回统一格式的错误信息，不产生部分写入
- 当工具结果包含存储引擎 Token、密码等敏感字段时，MUST 脱敏后返回（章程原则 VII §7.6）
- MCP 服务器 MUST 采用独立的 Bearer Token 认证，与现有 Web 管理 Basic Auth 体系隔离；MCP 端点 MUST 无绕过认证的访问路径

## 需求 *（强制）*

### 功能需求

- **FR-001**：系统必须提供 MCP 服务器，使 AI 客户端能够连接、发现工具并调用工具完成业务操作
- **FR-002**：MCP 工具必须按模块分组（存储引擎、同步任务、转码任务、Webhook、系统运维），一个 MCP 服务器承载全部模块的工具
- **FR-003**：存储引擎模块必须提供工具：查询列表/单个、创建、更新、删除、连接测试、目录浏览、文件条目浏览
- **FR-004**：同步任务模块必须提供工具：查询列表/单个、创建、更新、删除、手动触发执行、启用/禁用定时调度、查看执行历史
- **FR-005**：转码任务模块必须提供工具：查询列表/单个（含进度）、创建、重试、清理残留临时文件、批量删除失败/已完成任务、重试全部失败任务
- **FR-006**：Webhook 模块必须提供工具：规则查询列表/单个、创建、更新、删除、启用/禁用、事件分页查询；MUST NOT 提供事件注入/模拟发送工具，Webhook 事件仅由外部系统真实触发
- **FR-007**：系统运维模块必须提供工具：仪表盘统计查询、诊断包生成
- **FR-008**：MCP 服务器必须要求认证后才能调用工具，采用独立 Bearer Token 认证——新增 MCP 专用访问令牌配置项，令牌与 Web 管理界面 Basic Auth 凭据隔离；未认证或无效令牌请求 MUST 被拒绝，拒绝响应不泄露任何业务数据
- **FR-009**：MCP 工具调用 MUST 遵循分层架构——工具层只做参数适配与结果封装，业务逻辑复用现有 Service 层，禁止跨层调用（章程原则 I）
- **FR-010**：每次 MCP 工具调用 MUST 通过 TraceContext 注入唯一 traceId 与 module/operation 结构化字段，日志符合原则 VII
- **FR-011**：MCP 工具返回结果 MUST 对敏感字段（Token、密码等）脱敏，不得泄露凭据原始值（章程原则 VII §7.6）
- **FR-012**：MCP 服务器 MUST 默认禁用，通过配置显式开启后才提供服务；未配置有效的 Bearer Token 时 MUST 强制不可用；启用时与主应用同进程同端口提供服务，禁用时 MUST 不影响现有 Web 管理界面与 `/api/**` API
- **FR-013**：MCP 工具粒度采用混合模式——以操作级细粒度工具为主，覆盖现有 Web 管理 API 的全部核心操作面；另提供少量流程级快捷工具（如"执行一次同步流程"）供常见业务场景一键完成
- **FR-014**：触发长时间任务（同步、转码）的工具 MUST 采用异步提交模式，立即返回任务 ID，任务结果通过查询工具获取
- **FR-015**：MCP 工具调用发生业务异常时 MUST 返回包含错误原因的统一错误结构，便于 AI 理解并修正参数后重试

### 关键实体 *（如果功能涉及数据则包含）*

- **MCP 工具集**：按模块分组的工具集合，每个工具将 AI 请求映射到现有 Service 层方法并返回结构化结果
- **MCP 会话**：AI 客户端与 MCP 服务器之间的认证会话，决定工具调用的访问权限
- **存储引擎 / 同步任务 / 转码任务 / Webhook 规则 / Webhook 事件**：现有业务实体，MCP 工具操作的领域对象（复用现有实体与 DTO，不新建数据模型）

## 成功标准 *（强制）*

### 可衡量的结果

- **SC-001**：AI 用户可在 5 分钟内完成 MCP 服务器连接、认证并成功调用第一个工具（提供配置说明与连接示例）
- **SC-002**：MCP 服务器提供覆盖 5 个模块的工具集，以操作级细粒度工具覆盖现有 Web 管理 API 的全部核心操作面，并至少提供 1 个流程级快捷工具（五类模块合计约 30 项操作面）
- **SC-003**：100% 的 MCP 工具调用产生包含唯一非空 traceId 与 module/operation 字段的日志记录，可通过诊断包追溯完整调用链（章程原则 VII）
- **SC-004**：未认证或携带无效令牌的 MCP 请求 100% 被拒绝，且拒绝响应不泄露任何业务数据
- **SC-005**：工具返回结果中敏感凭据（Token、密码等）脱敏覆盖率 100%，日志与诊断包中无凭据原始值
- **SC-006**：启用 MCP 服务器后，现有 Web 管理界面与 `/api/**` API 的回归测试全部通过，无功能降级（MCP 作为增量能力，不改变现有行为）

## 假设

- MCP 服务器嵌入现有 Spring Boot 应用进程，与主应用同端口提供服务，默认禁用、通过独立配置开关启用（FR-012）
- MCP 工具调用不额外限流，复用现有 Service 层并发控制（YAGNI，章程原则 VI），若实测出现调用风暴再补充限流
- 采用标准 MCP 协议与主流传输方式（Streamable HTTP），兼容主流 AI 客户端（如 Claude Code、通用 MCP 客户端）
- MCP 工具复用现有 Service 层与 DTO，不重复实现业务逻辑，不新建数据模型
- 长时间任务（同步/转码）工具采用异步提交 + 任务 ID 返回模式，AI 通过查询工具获取结果
- 破坏性操作（删除任务/存储引擎、清理文件）随工具开放，但受 MCP Bearer Token 认证（FR-008）约束保护
- 本功能不引入新的数据实体与数据库表，仅增加 MCP 接入层与配置项
- 新增依赖（MCP 服务器实现库）需在 plan.md 的「复杂性追踪」中记录并证明合理性（章程原则 VI）
